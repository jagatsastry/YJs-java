# yjs-java

A faithful Java port of [Yjs](https://github.com/yjs/yjs) **v13.6.31** — the high-performance
CRDT framework for building collaborative applications — together with the parts of
[lib0](https://github.com/dmonad/lib0) **v0.2.99** that Yjs depends on.

The port is **wire-compatible** with the reference JavaScript implementation: updates produced by
this library are byte-identical to Yjs's, and updates produced by Yjs can be applied here (verified
against `yjs@13.6.31` from npm — see `CrossCompatTest`).

> Built with Test-Driven Development against Yjs's own test suite, biasing toward correctness and
> rigor. The CRDT (YATA) algorithm, binary encoding, and sync protocol are reproduced faithfully.

## Why a Java port?

Yjs is the de-facto CRDT for shared editing on the web. This port brings the same conflict-free
replicated data types — `Y.Map`, `Y.Array`, `Y.Text` (rich text), and `Y.Xml*` — to the JVM, so
JVM services and apps can participate in the same collaborative sessions as Yjs clients, exchanging
the exact same binary update messages.

## Build & test

Requires JDK 21+ and Maven.

```bash
mvn test          # run the whole suite
mvn -q test -Dtest=CrossCompatTest    # just the Yjs wire-compatibility tests
```

## Validation strategy

Correctness is established at several levels:

1. **Byte-exact `lib0`** — `Lib0EncodingTest` checks every encoder against golden vectors generated
   from the reference `lib0` (including the subtle negative-zero sign-bit trick in the OptRle
   encoders).
2. **Wire-compatibility with real Yjs** — `CrossCompatTest` loads updates generated by
   `yjs@13.6.31` and (a) applies them, reproducing identical state for map/array/text/xml in both
   V1 and V2; and (b) reproduces byte-identical updates for the same operations.
3. **Multi-client fuzz convergence** — `FuzzConvergenceTest` (via the ported `TestHelper`) runs
   randomized concurrent operations across 5 replicas with random disconnect/reconnect, then asserts
   every replica — and freshly merged replicas — converge to identical state (JSON, deltas, state
   vectors, delete sets, struct stores, and snapshots all compared).
4. **Ported Yjs test suite** — the upstream `tests/*.tests.js` are ported to JUnit (`*Test.java`),
   preserving the original assertions.

## Architecture (mirrors Yjs)

```
dev.yjs.lib0     Encoder/Decoder, Binary, Json, Xoroshiro128plus PRNG, Observable
dev.yjs.structs  AbstractStruct, Item (YATA), GC, Skip, AbstractContent + 9 Content types
dev.yjs.types    AbstractType (+ list/map helpers), YArray, YMap, YText, YXml*, YEvent hierarchy
dev.yjs.utils    ID, StructStore, DeleteSet, Transaction, Doc, UpdateEncoder/Decoder V1+V2,
                 Updates (encode/apply), UpdateMerging (merge/diff/lazy), Snapshot,
                 RelativePosition, UndoManager, EventHandler
```

See [`PORTING_NOTES.md`](./PORTING_NOTES.md) for the type-mapping and naming conventions used
throughout (e.g. `client`/`clock` are `long`; JS integral numbers map to `Long`, non-integral to
`Double`; `Uint8Array` to `byte[]`).

## Example

```java
import dev.yjs.utils.Doc;
import dev.yjs.utils.Updates;
import dev.yjs.types.YArray;
import java.util.List;

Doc d1 = new Doc();
d1.getArray("items").insert(0, List.of("a", "b", "c"));

// Sync to another replica using a Yjs-compatible binary update
Doc d2 = new Doc();
Updates.applyUpdate(d2, Updates.encodeStateAsUpdate(d1));

System.out.println(d2.<Object>getArray("items").toJSON()); // [a, b, c]
```
